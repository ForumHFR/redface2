Point RF2 depuis le dernier post Codex (#2783020) :

 

On n'est plus au stade "skills/specs/protocole". Le repo a maintenant une vraie alpha lecture qui tourne, avec AAB Play interne. Dernier build canonique : 0.1.0-phase1d.1 / versionCode 29.

 

Ce qui est livré côté app :
- login HFR + cookies persistants ;
- drapeaux via API REST, plus via scrape HTML forum1f.php ;
- forum / catégories / sous-catégories / listes de topics via API REST ;
- lecture de topic réelle : HTML HFR -> AST PostContent -> rendu Compose natif, sans WebView ;
- pagination longue des topics, scroll vers numreponse, deep links HFR ;
- cache Room avec TTL, isolation par compte, purge logout / changement de compte ;
- prefetch anonyme des pages suivantes pour ne pas marquer les drapeaux comme lus ;
- CI verte, PR ouvertes vidées.

 

Changelog/specs :
https://forumhfr.github.io/redface2/
https://github.com/ForumHFR/redface [...] ANGELOG.md
https://github.com/ForumHFR/redface2/issues

 

État actuel : Phase 1D quasiment bouclée côté mécanique de lecture. Il reste surtout à stabiliser le rendu et les cas moisis HFR :
- images / smileys / GIFs : https://github.com/ForumHFR/redface2/issues/109
- blocs [fixed] / [code] : https://github.com/ForumHFR/redface2/issues/79
- perfs lecture topic / freeze / gros topics : https://github.com/ForumHFR/redface2/issues/117
- drapeaux lus/non-lus : comportement à repolir en fin de Phase 1
- recherche actuelle : seulement dans la liste chargée, la vraie recherche viendra après

 

Donc oui, les retours "ça plante sur tel topic", "tel post s'affiche mal", "ça rame en remontant", "ce GIF bouge pas", etc. sont utiles. Idéalement avec topic + page + action faite avant le crash/freeze.

 

Et continuez à poster des trucs tordus en BBCode, citations, fixed/code, images, smileys : c'est exactement le genre de saloperies qui aide à verrouiller le parser.
