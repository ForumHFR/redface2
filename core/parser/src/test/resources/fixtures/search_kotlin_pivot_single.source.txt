  2. Else if body contains the banner « Le moteur de recherche a trouvé des résultats

  3. Else → single-cat mode (explicit `cat=X`). Parse the listing only ; no pivot box.

Capture procedure :
- HFR's search form (`/search.php?config=hfr.inc`) is POST. Submitting it returns a 1-second
  meta-refresh wait page that redirects to `/forum1.php?recherches=1&...` (GET). Capturing
  the GET on `forum1.php` directly is the canonical way to reach the result listing.
- Default form values used : searchtype=1 (Tous les mots), titre=1 (les titres de sujets),
  daterange=2 (depuis le début), resSearch=20, orderSearch=1, cat= (toutes catégories),
  pseud= (no author filter), subcat=0.

Contract observed in this shape :
- Banner : `<b>Le moteur de recherche a trouvé des résultats dans les catégories suivantes :</b>`
- Pivot dropdown : `<select name="cat"><optgroup label="FORUM HardWare.fr"><option value="10*hfr.inc" selected="selected">Programmation</option></optgroup></select>`
  Option value format = `"<catId>*<config>"` (e.g. `"10*hfr.inc"`).
- Hidden post_cat_list : `<input type="hidden" value="|10*hfr|" name="post_cat_list">` —
  pipe-delimited list of `(catId, configShort)` tuples HFR matched. Here a single entry
  because only Programmation had hits. The trailing `*hfr` lacks the `.inc` suffix that
  appears in the dropdown — these two encodings are inconsistent on the wire.
- Echoed query : `<input type="hidden" value="KOTLIN" name="search" />` — HFR upper-cases
  the term for the echo (case irrelevant to the underlying match).
- Listing : standard `forum1.php` markup the existing parser already consumes
  (`sujet`, `sujetCase2..9`, `cCatTopic`, `cBackCouleurTab2/3/4`).
- Topic URLs use the legacy slug pattern :
  `/hfr/<CategorieName>/<SubcatName>/<slug>-sujet_<topicId>_<page>.htm`
- No deep pagination on this query (3 results well under `resSearch=20`).
