Banc de test images Redface 2 — passe #876

 

Ce sujet est un banc de test permanent pour le rendu des images dans Redface 2.
Chaque post ci-dessous regroupe une famille de cas numérotés « cas N.x » (N = numéro du post).

 

Protocole
- La référence est le rendu WEB HFR de ce même sujet (desktop, images cappées à ~90 % de largeur).
- Pour chaque cas testé, répondez : « cas N.x : OK/NOK + device + capture ». Un NOK sans capture reste à confirmer.
- App de référence : Redface 2 dev 0.33.0 — cette ligne est mise à jour à chaque lot livré, le sujet sert de fixture de non-régression permanente.
- Conditions à couvrir hors BBCode (à préciser dans vos réponses le cas échéant) : densité d'affichage élevée + grand écran ; première visite vs revisite (cache) ; mode avion à mi-chargement pour l'état d'erreur réel.
- Répondez avec les numéros de cas, sans citer les posts du banc en entier.

 

Sommaire
- post 2 : tailles bloc (cas 2.1 à 2.7)
- post 3 : petites images et inline (cas 3.1 à 3.5)
- post 4 : galeries pures (cas 4.1 à 4.4)

- post 6 : miniatures cliquables (cas 6.1 à 6.4)

- post 14 : cas ajoutés au Lot 0 (cas 14.1 — orientation EXIF) + réserve pour cas futurs

 

Erratum (19/07/2026)
Les attendus des cas 2.1, 2.2, 2.5, 2.7, 3.1, 4.4, 5.3, 6.3 et 9.2 ont été réécrits pour coller au contrat de rendu de la passe #876 : la décision inline/bloc est structurelle (une image isolée sur sa propre ligne devient un bloc — aucun seuil de taille type « 240 px » n'existe) et un attendu de taille ne promet jamais plus que « jamais agrandie au-delà du natif, bornée aux caps ». Le cas 14.1 (orientation EXIF) a été ajouté au post 14 le même jour — le banc passe de 44 à 45 cas. Les attendus 10.1/10.2 ont été précisés le soir même, après la matrice de décodage du Lot 0 (AVIF conditionné au décodeur du device — mesuré OK sur Android 16 émulé, KO sur S10e Android 12 —, SVG = état d'erreur stable, jamais de case fantôme). Le banc est ainsi SYNCHRONISÉ avec le contrat v1.4 gelé. (Éditions Claude Fable 5, demandées par XaTriX.)

attendu : jamais agrandi ; bridé par le cap hauteur max(400 dp, moitié d'écran) seulement si ses 1000 px natifs dépassent le cap, sinon taille native

attendu : ~90 % de la largeur, hauteur faible

 

cas 2.5 — très grande 4000x3000
attendu : bornée à ~90 % de largeur (en 4:3, la largeur borne avant le cap hauteur), rendu net, scroll fluide

POST 10 — formats exotiques et états d'erreur

 

cas 10.1 — AVIF seul
attendu : si le décodeur plateforme du device gère l'AVIF, l'image s'affiche (mesuré : OK sur émulateur Android 16, KO sur S10e Android 12 — le support dépend du device, pas seulement de la version d'Android) ; sinon état d'erreur STABLE dans le slot réservé — jamais de case fantôme. Le support AVIF logiciel garanti partout est un chantier séparé.

 

cas 10.2 — SVG seul
attendu : état d'erreur STABLE dans le slot réservé, jamais de crash ni de case fantôme (aucun décodeur SVG disponible : la plateforme répond « unimplemented » sur tous les environnements mesurés)

 

cas 10.3 — URL morte suivie d'un témoin valide (#813)
attendu : placeholder d'erreur STABLE (pas d'effondrement) + retry possible au refresh ; le témoin s'affiche normalement

 

cas 10.4 — galerie mixte : 1 morte entre 2 valides
attendu : la galerie ne s'effondre pas — placeholder au milieu, les deux valides normales et espacées
